# 教师 / 班级视角 · 最小可行方案（待评审）

> 状态：设计稿，未实施。对应六角色走查中「李老师（助教/辅导员）」的诉求——
> 看班级谁在用、谁的掌握度在掉、哪些知识点集体薄弱。
> 该能力引入新的实体与权限体系，超出个人空间产品边界，故单独立项评审。

## 一、产品定位

不做成"教学管理系统"，只做成**老师的观察窗口**：
老师发起一个"班级空间"，学生自愿加入并授权同步自己的学习画像（只读）。
学生的一切内容（笔记原文、反思答案原文）**默认不下发**，老师只看到聚合数据。

## 二、最小数据模型（3 张新表，不动现有表）

```
class_group（班级空间）
  id, name, teacher_id(→users.id), join_code(6位邀请码), created_at

class_member（成员关系）
  id, class_id, student_id(→users.id), share_scope(see_scores|see_heatmap), joined_at
  unique(class_id, student_id)

mastery_snapshot（掌握度快照，每日一行）
  id, student_id, node_id, subject, mastery_score, reviewed_at, date
```

现有 `reflection_records`、图谱数据**零改动**；快照由夜间任务（APScheduler 已有）
从各学生掌握度聚合生成，学生未授权则不生成该学生的行。

## 三、接口（约 6 个）

| 接口 | 说明 |
|---|---|
| `POST /classroom` | 老师建班，返回 join_code |
| `POST /classroom/join` | 学生凭 join_code 加入（加入即授权 see_scores） |
| `GET /classroom/mine` | 老师看自己班级 / 学生看自己已加入的班级 |
| `GET /classroom/{id}/overview` | 成员掌握度热力（学生×学科矩阵） |
| `GET /classroom/{id}/weak-nodes` | 集体薄弱知识点 Top N（按成员平均掌握度排序） |
| `DELETE /classroom/{id}/member/{sid}` | 学生退出 / 老师移除 |

## 四、页面（1 个新路由）

`/classroom`：老师视角为"班级看板"——顶部成员数/平均掌握度，中部热力矩阵
（echarts heatmap，复用反思页雷达的按需引入方式），底部"集体薄弱点"卡片列表，
每张卡片带"建议全班复习"的提示文案。
学生视角同路由渲染"我的班级"——仅显示自己已授权的说明与退出入口。

## 五、明确不做的（防止范围膨胀）

- 不做作业 / 布置任务 / 批改——那是另一个产品
- 不做学生笔记内容查看——只看聚合分数与薄弱点
- 不做班级聊天 / 通知——通知能力复用现有 notifications 站内信即可
- 不做导入名单——加入靠邀请码，避免老师收集学生手机号的合规问题

## 六、预估工作量

后端：模型 3 表 + 迁移 + 6 接口 + 快照定时任务 ≈ 1~1.5 天
前端：1 页面 + 路由 + 热力图组件 ≈ 1 天
测试：接口与权限边界（老师≠成员、未授权不可见）≈ 0.5 天

## 二、技术栈与数据存储

| 层 | 技术 | 存储位置 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite + Pinia + Vue Router + Element Plus + ECharts | — |
| 后端 | FastAPI + SQLAlchemy(async) + Pydantic v2 + APScheduler | — |
| 关系库 | SQLite（开发态，`backend/krp.db`）；PostgreSQL 16（生产，docker-compose，端口 5432） | `backend/krp.db` |
| 图数据库 | Neo4j 5.26（节点/边 + 原生向量索引；Bolt 7687 / HTTP 7474） | bolt://localhost:7687 |
| 缓存/队列 | Redis 7（端口 6379；不可用时降级为万能验证码） | — |
| 大模型 | 华为云 MaaS：LLM（知识抽取/出题/对话）+ bge-m3 Embedding（1024 维） | `app/services/providers/maas_provider.py` |
| 图片识别 | 多模态视觉模型（`OCR_*` 配置，OpenAI 兼容；图片笔记上传时同步识别为文本） | — |
| 文件 | 上传文件静态目录 | `backend/uploads/`（HTTP `/uploads`） |

> 关键约定：**知识图谱的节点/边存 Neo4j，不落 ORM**；`app/models/` 只描述 SQLite 中的关系表。

### 3.1 入口与调度

| 文件 | 职责 |
| --- | --- |
| `main.py` | 创建 FastAPI 实例；`lifespan` 内执行 `ensure_schema()` 建表迁移、按 `SCHEDULER_ENABLED` 启停调度器；挂载 `/uploads` 静态目录；提供 `/health`；注册统一异常处理中间件（响应体 `{code, message, detail, trace_id}`，Neo4j 不可用→503）。 |
| `scheduler.py` | APScheduler 每日反思任务：`run_daily_reflection_job()` / `setup_scheduler()` / `shutdown_scheduler()`。 |

### 3.2 接口层（`api/`）

| 文件 | 职责 |
| --- | --- |
| `api/deps/` | 依赖注入包（按业务域拆分，`__init__` 全量再导出）：`auth_deps`（当前用户 / 可选用户）、`ai_deps`（AI 服务工厂）、`graph_deps`、`notes_deps`、`reflection_deps`、`avatar_deps`、`notification_deps`。 |
| `api/v1/router.py` | 聚合 8 个子路由并统一前缀 `/api/v1`。 |

**端点模块（`api/v1/endpoints/`）**

| 文件 | 前缀 | 主要能力 |
| --- | --- | --- |
| `auth.py` | `/auth` | 发送验证码、登录、`GET/PUT /me`（含昵称读改）。 |
| `notes.py` | `/notes` | 笔记列表、上传（解析+抽取入库）、详情、删除、重新抽取。 |
| `graph.py` | `/graph` | 书列表/三级树、节点类目知识点 CRUD、边、节点来源、AI 摘要、`subject-stats`、按 `user_id` 取全图。 |
| `reflection.py` | `/reflection` | 今日问题、作答评分、历史、掌握度趋势、复习调度查询/修改。 |
| `avatar.py` | `/avatar` | 分身头像图上传、发布/配置/取消发布、我的/详情、统计、会话列表/详情。 |
| `notifications.py` | `/notifications` | 通知列表、标记已读。 |
| `community.py` | `/community` | 帖子列表/我的/详情/发布/可见性/删除、点赞、克隆(fork)、封面图上传、评论列表/发布（含二级回复）/删除（级联整条线程）。 |
| `pet.py` | `/pet` | 状态、语音设置、收获、投喂、流式聊天。 |

| `reflection_service.py` | 反思问题生成、评分、历史、掌握度、调度。 |
| `pet_service.py` | 宠物身份生成、成长值累计与果实结算（`KNOWLEDGE_PER_FRUIT=10`、`MAX_TREE_FRUITS=8`、`GROWTH_PER_NODE=1.25`）、奖牌分档。 |

## 五、分层与依赖方向

```
  浏览器 SPA (Vue3)
        │  HTTP / WebSocket  (/api/v1)
        ▼
  接口层  api/v1/endpoints  ──(依赖注入)──  api/deps
        │
        ▼
  业务层  services/*  ──────────────►  providers/*（LLM / Embedding / Vision）
        │
        ├──►  图数据库  Neo4j（services/graph）
        ├──►  关系库    SQLite / PostgreSQL（models）
        └──►  缓存      Redis

  横切（各层复用）：core/  config · database · security · logger
                         · exceptions · middleware · prompt_manager
```

**命名与分层约定：**

- **后端**：`endpoints` 只做参数校验与编排，业务下沉 `services`；`schemas` 按域一一对应端点；图数据统一走 `services/graph`；Prompt 统一走 `app/prompts/` + `PromptManager`；全局常量集中 `core/constants.py`。
- **数据库**：SQLite 表结构由 `models` 定义，运行时变更通过 `core/schema_migrations.py` 登记补列。
- **前端**：网络访问统一经 `api/index.js`；全局状态用 Pinia；页面在 `views/`（按域分子目录）、可复用件在 `components/`、布局在 `layouts/`；ECharts 统一经 `utils/echarts.js` 按需引入。
- **降级**：Redis / Neo4j 不可用时优雅降级，不阻断主流程。
